# React SSR example

Standalone React SSR app. It imports no other example app and no Preact runtime.
Only UI components are shared through `@smolter/ui`.

```sh
pnpm install # repository root
pnpm --filter @smolter/example-react-ssr dev
pnpm --filter @smolter/example-react-ssr build
```

Open http://127.0.0.1:5175.

- `/`: counter, fetcher POST, automatic and manual revalidation.
- `/tasks`: loader-backed list and route-targeted create form.
- `/tasks/:id`: PATCH to rename, DELETE to remove, validation errors, no-op revalidation skip.
- `/about`: why data belongs outside components.

Server loaders/actions own the data. The build strips their re-exports from browser modules. Browser navigation and fetchers call the generated /_smolter transport. The task detail route also exports clientLoader/clientAction, which call serverLoader/serverAction. SSR preloads the same route loader and hydration reuses its data.

The flat file table is generated by `fileRouter()` in `vite.config.ts`.
`src/manual-routes.ts` is the server-side equivalent of the generated route table; `src/manual-browser-routes.ts` is the matching typed browser table using `serverRoute`. To use manual routing, import these tables in `main.ts` and `server.ts` instead of the virtual module. The production HTTP host already dispatches to the server table.

Version remains 0.0.1. Run `pnpm --filter @smolter/example-react-ssr start` after building to serve the production bundle on port 3000 (or set `PORT`). The included HTTP host dispatches data requests to `handleRequest` and HTML requests to `render`.

Use `SMOLTER_ROUTES=manual pnpm --filter @smolter/example-react-ssr dev` to select the explicit route tables. File routing is the default.
