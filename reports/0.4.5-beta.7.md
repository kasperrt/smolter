# 0.4.5-beta.7 streaming correctness report

## Reproduced behavior and fixes

1. **Late route content:** the production outer-Suspense fixture reproduced beta.6 inserting resolved homepage content after navigation. Checking only document completion missed the renderer’s later animation-frame work. New tests wait for two frames and assert absence of both fallback and resolved content. Preact application outlets now render two inert template anchors and capture only the original Suspense comment markers between them. A committed different route component removes those markers, preventing delayed renderer islands from targeting an abandoned range. Persistent root ranges are outside the anchors; routes reusing the same component retain ownership. Plain RouterProvider outlets keep their existing markup. No renderer hooks, copied renderer, dependency patch, observer, polling or text-based cleanup is used.

2. **Root revalidation:** expanded outer-Suspense coverage exposed an exception when a pending Await switched directly to a synchronous child. Keeping the inner Await component identity stable fixes that transition. The previously failing root-revalidation scenario now passes while preserving input and count.

3. **Interrupted document:** Chromium can retain readyState=loading after the server destroys the response and deliver no usable page-level completion/error event. The old 30-second default therefore did not satisfy a ten-second failure-UI expectation. The default total deferred budget is now 8 seconds, measured from payload revival. This is a bounded timeout policy, not immediate disconnect detection. The same existing one-shot timer is used; there is no polling, duplicate request or retry. Intentionally slower initial data can retain a longer explicit deferredTimeout. Both fallback styles reach failure UI within ten seconds in real interrupted-response tests without a timeout override.

## Compatibility

No new imports, public options or dependencies. The default deferred budget changes from 30,000 to 8,000 ms for both adapters. Applications intentionally awaiting initial deferred values longer than eight seconds must set deferredTimeout explicitly, for example 30_000. Values settled before the deadline remain valid, and explicit longer budgets are tested with a twenty-second simulated settlement. This budget does not restart when individual values settle.

Preact RouterApplication outlets add inert template anchors that do not create layout boxes or visible/accessibility content. Root controls remain mounted. Arbitrary Preact-only applications outside Smolter and arbitrary native lazy-boundary combinations are not claimed repaired. The tested contract covers Await inside native Suspense and its existing explicit fallback mode.

## Reproduction

Use the public Preact APIs to render a persistent root with an input, counter, navigation control and Outlet. The home loader returns `{ optional: pendingPromise }`; Home renders `<Suspense fallback={<p>Optional data pending</p>}><Await resolve={data.optional} errorElement={<p>Optional failed</p>}>{value => <p>{value}</p>}</Await></Suspense>`. Render through renderApplication with earlyHydration=true and the public Node handler; mountApplication hydrates the browser. Build/minify the browser entry for production.

Increment the counter and fill the input while document.readyState is loading. Navigate to another route, settle the original promise, wait for document load and two animation frames. Assert that only the new route remains and controls retain state. For interruption, destroy the original ServerResponse without settling its promise and assert failure UI within ten seconds; then navigate successfully and check retained controls.

Run `pnpm build`, then `pnpm exec playwright test tests/browser/suspense-deferred.spec.ts tests/browser/owned-deferred.spec.ts`. These cover both fallback styles, navigation/settlement races, return, opposite settlement order, nested rejection, persistent root boundaries, root revalidation, history and real response destruction. They use controlled promises rather than a slow fixed-duration loader.

## Release validation

Passed locally: lint, typechecking, generated-reference checks, size budgets, packed React 18/19 and Preact installs/SSR, consumer TypeScript 7 builds, JSR dry run, React/Preact production SSR smoke tests and the hosted Preact documentation smoke test. Coverage passed with 444 tests and 100% line coverage (2,207/2,207). Full Playwright runs passed 86 file-route tests and 86 manual-route tests, including the production-minified ownership fixtures, recovery, HMR, CSP and head-preservation regressions. These are upstream checks, not fresh Vibes or physical-device sign-off.

This beta is published through main CI to npm’s beta tag; latest remains stable. JSR publication is not part of this beta rollout.

CI additionally exposed intermediate nested-error and opposite-settlement locators matching both the visible main content and a hidden streamed island. Intermediate visibility assertions now scope to main; final post-navigation assertions still require stale content to be absent everywhere after document completion and two animation frames. This was a test selection race, not a relaxed ownership expectation.
