# Smolter 0.4.6: deferred client-loader data

## Behavior and scope

Integrated React and Preact applications previously recursively resolved a clientLoader's returned object before committing navigation. Version 0.4.6 awaits the top-level loader result but preserves nested promises, including their identity. Essential work can still be awaited inside the loader; optional work can render through Preact Await or React 19 use/Suspense with an error boundary. React 18 consumers can use an appropriate existing Suspense reader; React 18 does not provide use.

```ts
async function readStats(signal: AbortSignal) {
  const response = await fetch("/api/stats", { signal });
  if (!response.ok) throw new Error("Statistics unavailable");
  return response.json();
}
export function clientLoader({ signal }) {
  return { title: "Rooms", stats: readStats(signal) };
}
```

This changes shared route preparation, not either renderer. A local recursive observer handles rejected promises after abandonment or speculative loading without replacing them or hiding errors from mounted boundaries. Arrays, plain objects, repeated references and cycles are covered. Consumed data prefetches transfer their abort ownership to the consuming navigation, so optional signal-aware requests stop when that navigation is abandoned. A nested rejection is boundary data, not a top-level failed prefetch; successful payloads remain reusable.

Server JSON transport and action-result normalization are unchanged. Existing SSR early hydration and its 8-second default deadline are unchanged. Client-created promises do not inherit that deadline: loader code owns cancellation and any request deadline. No new dependencies, public exports, polling, server protocol or consumer workarounds were added.

## Reproduction and regression evidence

The before-fix public-API unit reproduction prepares a clientLoader returning data({ optional: pendingPromise }), navigates to it, and checks completion while the optional gate remains closed. It failed on the unchanged 0.4.5 implementation and passes after the fix. A separate consumed-prefetch signal test also failed before the ownership fix and passes afterward.

Six focused unit tests cover top-level gating, nested identity and cycles, abandoned rejection, prefetch/fetcher/revalidation reads, unchanged action/ordinary-loader normalization, and consumed-prefetch cancellation.

Production-minified SSR/browser fixtures use public mountApplication, renderApplication and createRequestHandler APIs with both React and Preact. A persistent shell contains input, counter and navigation controls. Client navigation returns optional HTTP data held behind an explicit server gate. Tests assert destination and fallback visibility before releasing the request, exactly one initial optional read, working controls and retained input. Scenarios include resolution, rejection, navigation away, deliberately uncancelled late settlement, and revalidation. Late-settlement assertions wait for completion and animation frames, then assert absence of abandoned fallback and resolved content across the document. These are upstream fixtures, not Vibes tests.

## Performance and limits

The controlled fixtures prove navigation and shell interaction can complete while optional client data remains pending. No statistical navigation benchmark, TTFB, LCP, CLS, request-count improvement or superiority over another router is claimed. No new Vibes, native/device, offline/CDN or deployment matrix sign-off is implied. Existing recovery, streaming, HMR and package regressions remain release gates.

No configuration migration is required. Consumers choosing deferred client data must render a fallback and error boundary, pass the signal to cancellable requests and choose application deadlines where needed. A client loader may explicitly await optional work to retain its previous blocking behavior.

## Release validation

Local validation passed: lint, typechecking, generated-reference checks, 450 tests with 100% line coverage, 88 production/browser tests in each file/manual routing mode, packed React 18/19 and Preact consumers using TypeScript 7, JSR dry-run package validation, production examples and SSR smoke tests, hosted documentation hydration/navigation/size checks, and whitespace validation. The initial browser command encountered an unrelated existing server on port 4173; rerunning on dedicated test ports passed without stopping that server.
