# Smolter 0.4.7: Node response cancellation

## Reproduced defect

On 0.4.6, a client disconnect while the renderer is awaiting data can leave the outgoing Node response closed before a Web Response becomes available. The adapter then tries to pipe that late response to the closed destination and forwards ERR_STREAM_UNABLE_TO_PIPE to middleware. A clean disconnect after streaming starts similarly forwards ERR_STREAM_PREMATURE_CLOSE. These are local HTTP reproductions of the reported errors; they do not establish why production connections closed.

The regression uses a real ephemeral HTTP server and public createRequestHandler behavior, with a renderer held behind a controllable promise:

1. Request a document or `/room.__smolter` data URL.
2. Wait until rendering starts, then abort the client request and wait for the Node response to close.
3. Release the renderer with a cancellable ReadableStream response.
4. Verify the Web Request signal is aborted, the body is cancelled exactly once, no headers are written after closure, and error middleware is not called.

Both document and data variants fail before the fix. Running all thirteen new cases against unchanged 0.4.6 on Node 26.12.1 produces eight failures; all thirteen pass after the fix. A separate active-body case sends the shell, then aborts the client, and verifies source cancellation without forwarding a clean disconnect. No timing sleeps or production endpoints are used.

## Implementation and error ownership

The Node adapter cancels an unread response body when its destination has already ended or closed. Request conversion also recognizes an already-closed destination and aborts its signal immediately.

During streaming, a close listener records a clean downstream disconnect before pipeline performs its own destruction. It checks the source and destination error state: a renderer or write failure can also close the destination, so destroyed status alone cannot classify an error as cancellation. The listener is removed after pipeline settles. Genuine render, source and destination failures retain error reporting, including source failures carrying ECONNRESET or ERR_STREAM_PREMATURE_CLOSE. An unread body's rejected cancellation also propagates. Original stream errors take precedence over pipeline's generic premature-close error.

The response still uses Node pipeline backpressure and existing compression flushing. No retry, timer, public API, dependency, browser protocol or renderer-specific behavior was added. Consumers need no configuration migration. Request signals remain the mechanism for cancelling application-owned backend work; the adapter cannot cancel unrelated work that ignores those signals.

## Runtime

Development, coverage, browser, docs and release builds now use Node **26.12.1**, recorded in `.node-version`. The two-version CI matrix checks Node 22 (latest patch) and 26.12.1. This replaces the Node 24 tooling run rather than adding another full CI matrix run. Consumer runtime requirements are unchanged.

Node 26.12.1 is the [2026-10-21 security release](https://nodejs.org/en/blog/release/v26.12.1/), including the high-severity Brotli fix CVE-2026-111497. Upgrading the package does not update a consumer's deployed Node runtime; that must be updated separately.
