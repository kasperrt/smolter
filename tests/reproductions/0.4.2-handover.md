# Smolter 0.4.2 consumer handover

Scope: Smolter only. No Vibes files, external repositories, production infrastructure or databases were changed. This release does not sign off Vibes UI/native/device parity.

## Consumer migration

Upgrade registry-backed `@kasperrt/smolter` dependencies and the lockfile to 0.4.2 once publication is verified. Do not add package patches, source aliases, local links or a replacement router. Preserve unrelated native patches.

For every early-hydrated deferred field, including persistent root fields, replace native Preact Suspense wrapping with Smolter's integrated fallback:

```tsx
import { Await } from "@kasperrt/smolter/preact";

<Await resolve={data.optional}
  fallback={<p>Optional data pending</p>}
  errorElement={<p role="alert">Optional data unavailable</p>}>
  {(value) => <p>{value}</p>}
</Await>
```

Continue using `renderApplication(request, routes, root, entry, { earlyHydration: true })` and `mountApplication(routes, root, existingOptions)`. No separate streaming entrypoint is required. Preserve deployment options, scoped transport endpoints, CSP nonce wiring, asset bases and root stylesheet links.

The server sends ordinary fallback HTML and existing deferred settlement packets. A mounted component updates its own content. Cleanup rejects updates from abandoned owners; source identity suppresses old results when a promise prop changes. No native Suspense markers are needed for this path, no requests are added, and shell inputs remain mounted. With early hydration, deferred results require JavaScript rather than arriving as resolved section HTML. Ordinary non-early SSR still streams resolved HTML.

**Compatibility limit:** this does not repair native Preact streamed Suspense or arbitrary lazy component boundaries. Await without fallback retains its old Suspense behavior. The required early-hydration migration applies to root sections as well as route sections. Published Preact 11.0.1 and preact-render-to-string 6.8.1 are used without patches. The original native diagnostic is preserved under tests/reproductions and remains reproducibly broken; it is not represented as fixed or included in the Smolter-path pass count. The supported thirteen-case matrix keeps the same stale-content, state, focus and ownership assertions as the diagnostic.

## File routing

```text
src/routes/robots[.]txt/route.ts       → /robots.txt
src/routes/sitemap[.]xml.ts           → /sitemap.xml
src/routes/feeds.rss[.]xml/route.ts    → /feeds/rss.xml
src/routes/[.]well-known.security[.]txt/route.ts → /.well-known/security.txt
```

Dots outside `[.]` remain segment separators. Rename any filename that previously needed a dotted URL override and remove `export const id` and `export const routePath` from file route modules. Both eager/SSR and lazy generation reject those overrides with a migration message. Use the generated path for targeted revalidation; root remains `root`. Manually declared route arrays retain explicit IDs and paths. No browser runtime changes are needed for filename parsing.

## Other correctness changes

- Pending page and independent fetcher submissions share deployment recovery ownership. Completing or disposing one cannot release another's protection. Stale checks cannot consume the recovery marker after mutations finish.
- Replacing a watcher detaches the previous owner without stacking wrappers. An old cleanup cannot restore stopped methods over the replacement. Pending mutation protection survives replacement.
- Initial deferred values have one total deadline, default 30,000 milliseconds. `mountApplication` accepts `deferredTimeout` as an integer from 1 through 2,147,483,647. Invalid values throw. It is not an inactivity timer and does not reliably detect abrupt network loss immediately. Expiry rejects unfinished values, keeps settled values, ignores late packets and releases lifecycle state on disposal. It does not retry requests or mutations.

## Reproduction and verification

Use a minified production SSR fixture with a persistent root input, count button, navigation button and Outlet, plus Scripts. The `/` loader returns `{ optional: new Promise(resolve => gate = resolve) }`. Render it through the Await snippet above. The navigation button calls `router.navigate('/destination?pending=1#scope')`; that route renders `<h2>Destination ready</h2>`. Use `createRequestHandler` with `dispatchRoute` for the public data endpoint so the adapter normalizes its URL parameter.

1. Open `/`, confirm fallback and working shell controls while the gate is unresolved.
2. Fill the persistent input and click the counter once.
3. Navigate to the destination; then resolve the old gate.
4. Wait for document completion.
5. Assert destination and query/hash remain, old fallback **and** resolved content are absent, input value/focus persist, counter is one and no initial loader was duplicated.

The production gate extends this to settlement racing navigation, return, adjacent reverse settlement, nested rejection, both persistent-root settlement orders, repeated navigation, rejection after leaving, root revalidation, history, controlled interruption and actual two-second interruption. Separate streaming cases cover mutation/root refresh, CSP, and marked head scripts/styles. Unit/public-API regressions cover pending submission failures/disposal, watcher replacement, deadline validation and stale promise replacement.

Run the supported release checks with `pnpm coverage`, `pnpm smoke`, `SMOLTER_ROUTES=manual SMOLTER_TEST_PORT=4473 pnpm smoke`, `pnpm pack:smoke`, `pnpm jsr:check`, `pnpm build:examples`, `pnpm smoke:production`, `pnpm build:site`, `pnpm smoke:site`, `pnpm lint`, `pnpm typecheck`, `pnpm docs:check` and `pnpm size`.
